# 1. AUTENTICACIÓN
# ═══════════════════════════════════════════════════════

# ───────────────────────────────────────────────────────
# 1.1 REGISTRO DE USUARIO
# ───────────────────────────────────────────────────────
# Esta ruta te permite crear un nuevo usuario en el sistema.

Método: POST

URL: http://127.0.0.1:8000/api/register/

Headers:
  Content-Type: application/json

Body (raw > JSON):
{
  "username": "usuario123",
  "email": "usuario@example.com",
  "password": "password123",
  "first_name": "Juan",
  "last_name": "Pérez"
}

Resultado esperado:
- Status: 201 Created
- Devuelve los datos del usuario creado (sin el password)
- El usuario ya está guardado en PostgreSQL

# ───────────────────────────────────────────────────────
# 1.2 OBTENER TOKENS DE ACCESO (LOGIN)
# ───────────────────────────────────────────────────────
# Uso de SimpleJWT para autenticación. Necesitarás el token de acceso
# para las rutas protegidas (órdenes, perfil, personalizaciones).

Método: POST

URL: http://127.0.0.1:8000/api/login/

Headers:
  Content-Type: application/json

Body (raw > JSON): Envía el username y password que acabas de registrar.
{
  "username": "usuario123",
  "password": "password123"
}

Resultado esperado:
- Status: 200 OK
- Devuelve un objeto JSON con:
  {
    "refresh": "eyJ0eXAiOiJKV1QiLCJhbGc...",
    "access": "eyJ0eXAiOiJKV1QiLCJhbGc...",
    "user_name": "Juan",
    "user_email": "usuario@example.com"
  }

IMPORTANTE: 
- Copia el valor de "access" (el token JWT)
- Este token dura 1 día según la configuración
- Lo necesitarás para todas las rutas protegidas
- En Postman, guárdalo como variable de colección llamada "token"

# ───────────────────────────────────────────────────────
# 1.3 REFRESCAR TOKEN
# ───────────────────────────────────────────────────────
# Cuando el access token expire, usa esta ruta para obtener uno nuevo
# sin tener que hacer login de nuevo.

Método: POST

URL: http://127.0.0.1:8000/api/token/refresh/

Headers:
  Content-Type: application/json

Body (raw > JSON):
{
  "refresh": "TU_REFRESH_TOKEN_AQUI"
}

Resultado esperado:
- Status: 200 OK
- Devuelve un nuevo "access" token

# ═══════════════════════════════════════════════════════
# 3. PERFIL DE USUARIO (REQUIERE AUTENTICACIÓN JWT)
# ═══════════════════════════════════════════════════════
# ⚠️ Para estas rutas, debes agregar el header de autorización:
#    Authorization: Bearer TU_TOKEN_DE_ACCESS

# ───────────────────────────────────────────────────────
# 3.1 VER PERFIL DEL USUARIO AUTENTICADO
# ───────────────────────────────────────────────────────

Método: GET

URL: http://127.0.0.1:8000/api/profile/

Headers:
  Authorization: Bearer TU_TOKEN_DE_ACCESS

Cómo agregar el token en Postman:
1. Ve a la pestaña "Authorization" o "Headers"
2. Si usas Headers: Agrega un nuevo header
   - Key: Authorization
   - Value: Bearer eyJ0eXAiOiJKV1QiLCJhbGc... (pega tu token después de "Bearer ")
3. Si usas Authorization: Selecciona Type "Bearer Token" y pega el token

Resultado esperado:
- Status: 200 OK
- Datos del usuario autenticado

Ejemplo de respuesta:
{
  "id": 1,
  "username": "usuario123",
  "email": "usuario@example.com",
  "first_name": "Juan",
  "last_name": "Pérez"
}

# ───────────────────────────────────────────────────────
# 4.2 CREAR UNA ORDEN NUEVA
# ───────────────────────────────────────────────────────
# Esta es la ruta más importante para el proceso de compra.
# Crea una orden completa con múltiples items (productos) de una vez.

Método: POST

URL: http://127.0.0.1:8000/api/orders/

Headers:
  Authorization: Bearer TU_TOKEN_DE_ACCESS
  Content-Type: application/json

Body (raw > JSON):
{
  "shipping_address": "Av. Reforma 123, CDMX, México",
  "items": [
    {
      "product": 1,
      "variant": 2,
      "quantity": 2,
      "customization_fee": 50.00
    },
    {
      "product": 3,
      "quantity": 1,
      "customization_fee": 0
    }
  ]
}

Explicación de los campos:
- shipping_address: Dirección completa de envío (obligatorio)
- items: Array con los productos de la orden (mínimo 1)
  - product: ID del producto (obligatorio)
  - variant: ID de la variante/talla (opcional, usar si el producto tiene tallas)
  - quantity: Cantidad a ordenar (mínimo 1)
  - customization_fee: Costo extra por personalización (default: 0)

VALIDACIONES AUTOMÁTICAS:
- Si se especifica "variant", se valida que haya stock suficiente
- Si no hay stock, devuelve error 400 con el mensaje
- El stock se descuenta automáticamente al crear la orden
- El total se calcula automáticamente: (precio + customization_fee) * quantity

Resultado esperado:
- Status: 201 Created
- La orden completa con todos sus items
- El campo "total_amount" ya calculado
- Los IDs de order e items para referencias futuras

# ───────────────────────────────────────────────────────
# 4.4 ACTUALIZAR ESTADO DE UNA ORDEN
# ───────────────────────────────────────────────────────
# Útil para marcar una orden como pagada o enviada, y agregar tracking.

Método: PATCH

URL: http://127.0.0.1:8000/api/orders/1/

Headers:
  Authorization: Bearer TU_TOKEN_DE_ACCESS
  Content-Type: application/json

Body (raw > JSON): Puedes actualizar solo los campos que necesites
{
  "status": "paid",
  "tracking_number": "TRACK123456"
}

Estados válidos:
- pending (pendiente - default)
- paid (pagado)
- shipped (enviado)

Campos actualizables:
- status
- tracking_number
- stripe_payment_id (para integración con Stripe)
- shipping_address

Resultado esperado:
- Status: 200 OK
- La orden actualizada con los nuevos valores

# ───────────────────────────────────────────────────────
# 5.1 CREAR PERSONALIZACIÓN
# ───────────────────────────────────────────────────────
# Adjunta un diseño personalizado a un item de una orden.

Método: POST

URL: http://127.0.0.1:8000/api/customizations/

Headers:
  Authorization: Bearer TU_TOKEN_DE_ACCESS
  Content-Type: application/json

Body (raw > JSON):
{
  "order_item": 1,
  "uploaded_image": "image/upload/v1234567890/custom_uploads/design.png",
  "base_color_hex": "#FF5733",
  "design_position_x": 0.5,
  "design_position_y": 0.3,
  "design_scale": 1.2
}

Explicación de los campos:
- order_item: ID del OrderItem (debe existir en una orden tuya)
- uploaded_image: URL de la imagen en Cloudinary
- base_color_hex: Color base del producto en formato hexadecimal
- design_position_x: Posición horizontal del diseño (0.0 a 1.0)
- design_position_y: Posición vertical del diseño (0.0 a 1.0)
- design_scale: Escala del diseño (1.0 = tamaño normal)

Nota: La imagen debe estar previamente subida a Cloudinary

Resultado esperado:
- Status: 201 Created
- La personalización creada con su ID

# ═══════════════════════════════════════════════════════
# TIPS ADICIONALES PARA POSTMAN
# ═══════════════════════════════════════════════════════

1. CREAR COLECCIÓN
   - En Postman, crea una nueva colección "Nordika Backend"
   - Agrupa las peticiones por categoría (Auth, Products, Orders, etc.)

2. USAR VARIABLES DE ENTORNO
   - Crea un entorno "Development"
   - Variable "base_url": http://127.0.0.1:8000
   - Variable "token": [pegar token después del login]
   - Usa {{base_url}} y {{token}} en las peticiones

3. GUARDAR TOKEN AUTOMÁTICAMENTE
   - En la petición de login, ve a la pestaña "Tests"
   - Agrega este script para guardar el token automáticamente:
     ```javascript
     var jsonData = pm.response.json();
     pm.environment.set("token", jsonData.access);
     ```

4. FORMATO DE FECHAS
   - Las fechas se devuelven en formato ISO 8601
   - Ejemplo: "2026-02-17T09:35:31-06:00"

5. CÓDIGOS DE RESPUESTA
   - 200 OK: Petición exitosa (GET, PUT, PATCH)
   - 201 Created: Recurso creado exitosamente (POST)
   - 400 Bad Request: Datos inválidos o faltantes
   - 401 Unauthorized: Token inválido o faltante
   - 404 Not Found: Recurso no encontrado
